# Спека: сравнение моделей на wiki-eval через CloseRouter

Дата: 2026-07-05. Статус: **одобрено владельцем в чате** (ответы на 4 вопроса, см. § Решения).
Исполнение: Scenario A, шаги 3–8 автономно. Тикеты: [docs/superpowers/plans/2026-07-05-model-comparison/tickets/](../plans/2026-07-05-model-comparison/tickets/).
Операционные документы эксперимента: [docs/experiments/2026-07-05-model-comparison/](../../experiments/2026-07-05-model-comparison/).

## Цель

Получить honest-метрики wiki-eval (recall M1/M2/M3, precision P1/P2, срезы, Wilson CI) для ≥3 моделей
через CloseRouter на **полном корпусе v2 (100 статей, 10 секций)**, плюс стоимость, скорость и
надёжность маршрутов — чтобы выбрать рабочую модель extractor+judge по трейд-оффу качество/цена/скорость.

## Модели (все ID проверены живой пробой каталога 2026-07-05)

| # | Модель | ID | Цена in/out, $/Mtok | Маршрут |
|---|---|---|---|---|
| 1 | gpt-5.5 | `openai/gpt-5.5` | 0.30 / 0.30 | **самый дешёвый стабильный** по triage (указание владельца) |
| 2 | deepseek-flash | `deepseek/deepseek-v4-flash` | 0.07 / 0.14 | лучший чистый по triage |
| 3 | qwen-3.7-plus | `qwen/qwen3.7-plus` | 0.20 / 0.80 | лучший чистый по triage |
| 4 | baseline | `google/gemini-3.1-flash-lite` | ~2e-6/вызов | `provider-9` (зафиксирован экспериментом 2026-07-05) |

## Решения владельца (чат, 2026-07-05)

1. **Корпус:** сразу полный v2-100 для всех моделей (GT строится в фоне, бесплатно).
2. **Роли:** модель-кандидат занимает обе роли — extractor **и** judge (меряем как полную замену в пайплайне).
3. **Baseline:** gemini-3.1-flash-lite@provider-9 идёт 4-й строкой сравнения.
4. **Бюджет:** жёсткий кап **$60** на весь эксперимент (CloseRouter-баланс ≈ $84).

## Дизайн — фазы

- **Ф0 — GT v2-100** (бесплатно, фон, ~1–2 ч из-за rate-limit Wikipedia/Wikidata):
  `wiki_eval.py build-gt --titles data/eval/wiki/titles_v2.txt --out data/eval/wiki/gt_v2.jsonl`.
  Fail-loud: >10 % статей с браком — стоп и разбор.
- **Ф1 — Triage маршрутов** per model (методика отчёта 2026-07-05): 10 проб на маршрут
  (`auto` + `provider-1..12`), классификация: доля 2xx, med/p90 латентность, **честность prompt-токенов**
  (паддинг >100 ток на ~10-токенном промпте = резеллер-обёртка, дисквалификация), surfaced `cost_usd`.
  Правило выбора: success ≥9/10 и честные токены → min цена/вызов → tie-break латентность.
  Урок прошлого эксперимента применяется: **пинить явный маршрут, не auto**.
- **Ф2 — Апгрейд раннера** (обязательный, иначе прогон 100 статей ≈ 6+ ч последовательно):
  параллельная extraction (кап 4, `DEFAULT_MAX_CONCURRENCY`), CLI `--model/--provider/--max-judge-calls`,
  учёт стоимости extraction в BudgetGuard (сейчас считается только judge — дыра в учёте),
  `meta.json` прогона (модель, маршрут, цены, spend, wall-clock), выходной путь
  `reports/terminology/wiki-eval/<model-slug>/<config>/<run_id>/`.
- **Ф3 — Матрица прогонов:** config `111`, 4 модели **параллельно фоном**, каждый прогон
  со своим `--max-usd 12`; перед стартом — dry-run форкаст каждого.
- **Ф4 — Отчёт:** агрегация оркестратором, сравнение моделей (recall/precision + CI, cost на 1k GT-кортежей,
  wall-clock, доля транзиентных ошибок, срезы по секциям/resolved_by/type), HTML на Tokyo Night →
  Claude Artifact + `docs/reports/`; заполнение шаблонных таблиц §5 (Часть 3); фиксация уроков в
  `docs/experiments/LESSONS.md`; doc-parity (`docs/stages/wiki-eval.md` § Status).

## Оценка стоимости (консервативно)

На модель при 100 статьях: ~12k extraction-вызовов (≈8.4M in / 1.2M out) + ~3k judge (≈3M in / 0.9M out).
gpt-5.5 ≈ $4–5; qwen ≈ $2.5–3; deepseek ≈ $0.8–1; gemini ≈ $0.1. Triage ≈ $1.
**Итого ≈ $10–12 при капе $60** (запас ×5 на ретраи/недооценку токенов).

## Риски и меры

- `MAX_JUDGE_CALLS=900` мал для 100 статей (~3k эскалаций) → выносится в CLI (Ф2), для прогонов 5000.
- CloseRouter ~90 % per-route success → ретраи 3×1/3/9с уже в клиенте; доля ретраев — в отчёт.
- Паддинг-провайдеры (урок gpt-5.4-mini: +4400 скрытых prompt-ток) → дисквалификация на Ф1.
- 4 параллельных прогона × кап 4 = ≤16 запросов in-flight суммарно, но по **разным** маршрутам — приемлемо;
  при всплеске 429 у одного прогона его ретраи не задевают остальных (процессы независимы).
- Прогон >30 мин → только фоном (указание владельца), лог прогресса в файл прогона.

## Критерии успеха

1. Для всех 4 моделей: `metrics.json` + `report.html` на полном gt_v2 (или явный разбор, почему модель выбыла).
2. Сравнительная таблица с CI и стоимостью; рекомендация «какую модель брать» с обоснованием.
3. Спенд ≤ $60; ни один прогон не убит капом молча (стоп = зафиксированная причина).
4. Отчёт доставлен артефактом; таблицы §5 заполнены реальными числами.
