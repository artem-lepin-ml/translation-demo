# Спека: подсветка терминов в переводе по pairAccuracy (волна 3, задача 3) — rev-2

Дата: 2026-07-02. Ветка: `feat/pair-highlight`. Статус: **rev-2 после /verify-spec (3 аспекта: 1 CRITICAL, 3 HIGH закрыты)**.

**Done when:** термины в Translation-панели подсвечены светофором pairAccuracy; null-вердикт никогда не выглядит зелёным; повторные вхождения термина маппятся корректно; одна каноническая схема CSS-классов вместо четырёх.

## Диагноз (verify-spec, 3 агента: реальность лучше и хуже, чем в rev-1)

Фича **уже реализована насквозь и мертва из-за рассинхрона имён**: `review-extension.ts:180` эмитит `pair-accuracy-${verdict}` + `data-pair-accuracy`; CSS стилизует только `.verdict-*` + `[data-verdict]` (мёртвые правила — их никто не эмитит); плюс отдельная семья `difficulty-*` на RU-стороне дублирует те же цвета. Итог: EN-спаны рендерятся нейтральной пунктирной рамкой, цвет/точка не загораются. Сверх того:
- **`pairAccuracy ?? 'green'` (review-extension.ts:177)** — незаземлённый термин (difficulty=red → pair=null) красится зелёным = UI визуально одобряет то, что система «не может оценить» (GlossaryTab тот же null честно рисует «—»).
- **Повторные вхождения**: `findLeftmost` кладёт ВСЕ декорации одного targetSurface на первое вхождение → при N повторах ломается cross-hover (последний data-term-id побеждает).
- Покрытие данных: 177/269 терминов (66%) отрисуемы; **абзац id=8 — ноль цветных терминов** (демо-риск); текущие вердикты — **placeholder-ротация `[i % 3]` в seed.py**, содержательными станут после seed-refresh.

## Решение

1. **Одна схема классов: `verdict-{green|yellow|red}` + `data-verdict`** (уже есть в CSS вместе с ::after-точкой). `review-extension.ts` переводится на неё; `pair-accuracy-*` эмиссия и мёртвый `difficulty-*`-дубль в CSS удаляются (difficulty-логика RU-стороны переводится на те же verdict-правила ИЛИ остаётся — планировщик выбирает меньший дифф, но параллельных дубль-правил с теми же цветами быть не должно).
2. **null-вердикт**: `?? 'green'` удаляется. `pairAccuracy null` при существующем targetSurface → нейтральный спан без цвета/точки (та же семантика «cannot assess», что в Glossary). `targetSurface null` → спан подавлен (как сейчас).
3. **Повторные вхождения**: маппинг по порядку — i-е RU-вхождение поверхности → i-е свободное EN-вхождение (`findOccurrences` с потреблением индексов вместо `findLeftmost`). Обе стороны уже деривят pairIndex из одного массива — синхронизация сохраняется.
4. Оба render-пути перечислены как touch-points: `review-extension.ts:buildDecorations` (EN, декорации) и `EditorParagraph.tsx:SourceWithTerms` (RU, React-спаны) + один CSS-блок. Конвенция различения «термины = dotted border, judge = solid box-shadow» фиксируется CSS-комментарием (она эмерджентна — защитить от будущего рефакторинга).
5. Протухание targetSurface после живого редактирования = принятое ограничение (спан молча гаснет; та же семантика, что у judge-подчёркиваний) — фиксируется в webapp.md, НЕ чинится.

## Не делаем

- Не меняем данные/пайплайн (вердикты остаются ротацией до seed-refresh — в отчёте владельцу это проговаривается); не добавляем легенду; не чиним протухание после правок.

## Критерии успеха

1. vitest на `buildDecorations` (файл сейчас не покрыт вообще): класс по каждому вердикту; null → нейтраль (НЕ green); повторные вхождения → раздельные позиции и корректные data-term-id; targetSurface null → нет декорации. + проверка «эмитируемый класс существует в variant-a.css» (grep-тест — ровно тот класс багов, что жил незамеченным).
2. e2e-скриншот: обе панели, слева difficulty, справа pair-палитра, cross-hover жив; абзац с одновременными термином и judge-подчёркиванием различим; **абзац id=8 в скриншоты не брать** (пустой).
3. English-only; doc-parity (webapp.md терминологический рендер + ограничение протухания) тем же коммитом.
