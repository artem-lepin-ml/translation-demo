Пайплайн Данила (BOUQUET, факты из `external/gse-translation/`):

- **Перевод** — `scripts/02_translate_json.py`: строго по-абзацно, без чанкинга и rolling-контекста;
  вход — плоский JSON-массив строк (`bouquet_original.json`, **198 абзацев**), выход `translation.json`

  всё в user через `gemma_universal.md` (репак Infomaniak, temp 0.7).
- **Судья** — `scripts/03_translation_scoring.py`: 1 вызов на критерий (файлы `prompts/03_scoring/universal/`:
  accuracy/fluency/style → 3 вызова/абзац), критерий-md = system-промпт, `response_format=json_object`;
  валидный выход: `final_score` int 1–10 + `identified_issues[{source_fragment, problematic_fragment,

  Судья BOUQUET = **`qwen3_6-27b` локальный vLLM, temp 0.7, top_k 20, `enable_thinking: True`**, конкурентность 360.
  Отчёт для refinement собирается автоматически в `evaluation/<run>/universal/reports/<judge>.jsonl`.
- **Refinement** — `scripts/04_refinement.py`: **один глобальный редактор `qwen3_6-27b` для всех систем**
  (в т.ч. для TranslateGemma — наша догадка В3 подтверждена), один вызов на абзац, issues всех критериев
  слиты в одно сообщение с группировкой `### {Criterion} issues`; нет issues → passthrough без вызова;
  system-промпт `04_refinement/system.md` **байт-идентичен** нашему `prompts/correction/system.md`.
  Свежий фикс `3c1703a`: strip + схлопывание переводов строк.
- **MetricX/COMET** — скриптов и зависимостей в репо НЕТ (считалось вне гита); известны только форматы входов
  (`{"source","hypothesis","reference"}` JSONL; wo_ref = `reference:""`; comet-вход кастомный `{"src","hyp","ref"}`)
  и выходов (`metricx/scores{,_wo_ref}.jsonl` с `prediction`; `comet/scores.json`). **Чекпоинты не названы нигде** — Д1.
  Прецедента reference-free COMET (CometKiwi) в его данных нет — для wiki строим сами.
- **Скрипта корреляций нет** (VENDORED.md) — 12 ячеек Спирмена Данил считал вне гита. Наш
  `scripts/judge_metric_stats.py` **написан и провалидирован** на его вендоренных выходах
  ([отчёт](../../reports/python-pro-bouquet-spearman-validation.md), дамп `reports/bouquet/judge_metric_stats.json`):
  23/24 ячейки скриншота воспроизведены точно (mean |residual| = 0.0000); его колонка «MetX» = **ref-based**
  MetricX (не QE); выброс — Qwen Accuracy/Comet (−0.0690 у него vs −0.0069 у нас), почти наверняка описка
  в десятичном знаке — уточнить у Данила вместе с Д1. Headline-средние тоже совпали. Новые числа для статьи:
  sign-agreement Δjudge×Δmetric на не-ничьих парах — accuracy 60–63% (обе системы, ожидаемое направление,
  tau_b −0.12…−0.17), fluency/style ≈ шум; средние дельты авто-метрик на refinement ≈ 0 (у TG даже слегка
  хуже: MetricX +0.013…+0.036) при позитивных judge-дельтах (+0.14…+0.21) — ровно та точка, где wiki-масштаб
  (×8 данных, n_nonzero_both сейчас всего 17–54) должен дать решающий ответ.
- **`<think>`-защиты в коде нет** — полагается на reasoning-parser vLLM-сервера. Наш гард (§ 4) — новый
  предохранитель, у Данила его нет.
- Наши `prompts/scoring/*` = его `v2` (байт-идентичны, кроме одного имени поля во fluency); `universal` —
  доменно-независимая тройка без terminology/cultural — именно оси скриншот-таблицы.

**Багов-капканов upstream не копируем (фиксы на нашей стороне):** (1) `--chunking` — обязательный, но мёртвый
аргумент; (2) `_build_out_dir` в `translate_json.py` захардкожен на `data/pilot/translating` — параметризуем;
(3) `gemma_universal.md` начинается с артефакта `<<<custom>>>`, уходящего в модель verbatim — для wiki-прогона
чистим и раскрываем дивергенцию; (4) refinement не пишет манифеста — наш обвяз сохраняет `config.json` рядом;
(5) `models.yaml` дрейфует от манифестов прогонов (порт 7000 vs 8000) — провенанс всегда по `config.json` прогона.

## 3. Модели и судья (решения приняты)

Оцениваемые системы — 4: `translate_gemma-27b` (репак Infomaniak, как у Данила), **`Qwen/Qwen3-4B-Instruct-2507`**
(решение В5: не-thinking, стабильный vLLM; в реестр Данила добавляется новой записью), `qwen3_6-27b`,
`deepseek/deepseek-v4-flash` (CloseRouter, пин маршрута; для него в `models.yaml` — запись с base_url CloseRouter).
Сэмплинг переводов = как у Данила (temp 0.7 у локальных; deepseek T=0.3, проба подтверждает reasoning_tokens==0).

**Судья.** Три роли конфига:
1. **Пилот (механика)** — вербатим Данила: `qwen3_6-27b`, temp 0.7, top_k 20, `enable_thinking: True`, universal.
2. **Primary (wiki + BOUQUET-ре-ран)** — **`qwen3_6-27b`, temp 0, `enable_thinking: False`**, те же universal-промпты.
   Та же модель-судья, что у Данила (сопоставимость осей), но детерминированная и без thinking: главная атака
   ревьюера — не стохастичность, а тройной конфликт (Qwen3.6 судит себя + рефайнит всех + пересуживает свои
   правки); primary-свидетельством статьи делаем строки TranslateGemma (там судья ≠ переводчик), self-judge
   qwen-строк раскрывается.
3. **Пробы поверх:** (а) test-retest вербатим-конфига: ~200 wiki-абзацев × 2 повтора × 3 критерия ($0, локально) —
   квантификация шума стохастического судьи (test-retest Spearman, % изменений ≥1, % флипов знака Δ);
   (б) **J′ = deepseek-v4-flash** на ~150 refined-абзацах (~$1–3) — межсудейское согласие;
   (в) BOUQUET-ре-ран под primary-конфигом → таблица с **двумя judge-колонками** (Данил-вербатим / fixed-J):
   дельта = измеренная чувствительность к сетапу судьи, а не молчаливый форк.

Редактор refinement: `qwen3_6-27b` для всех систем (вербатим Данила; self-refine из v2 отменён — паритет важнее).
GPU-раскладка: судья/редактор Qwen3.6 (TP=2, GPU2-3) поднят постоянно; TG (GPU0) и Qwen-4B (GPU1) — на фазу
перевода; MetricX/COMET — после освобождения, отдельный venv (пины 2023 у MetricX). Изоляция vLLM-версий
per-model — как в v2 (TG recipe 0.14.1+ / Qwen ≥0.19; смоук всех серверов одновременно в Ф0).
