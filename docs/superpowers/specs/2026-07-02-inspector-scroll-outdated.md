# Спека: попап правок — позиционирование, живой список, исчезновение перекрытых (волна 3, задача 2) — rev-2

Дата: 2026-07-02. Ветка: `feat/inspector-fixes`. Статус: **rev-2 после /verify-spec (3 аспекта: 2 CRITICAL, 2 HIGH закрыты)**.

**Done when:** Accept/Dismiss достижимы при любом числе карточек и высоте экрана; после принятия правки попап живёт дальше, а перекрытые правки исчезают из него и инспектора немедленно и целиком.

## Диагноз (verify-spec переписал мой)

1. ~~«Попап не скроллится»~~ — скролл УЖЕ есть (`max-height: 60vh; overflow-y: auto`). Реальный баг — **математика позиционирования** в `IssuePopover.tsx:18`: `top = Math.min(rect.bottom + 8, window.innerHeight - 320)` — захардкоженные 320px занижают реальную высоту стека карточек → попап вылезает за низ вьюпорта (недостижимые кнопки), на коротком экране top уходит в минус.
2. **Попап закрывается при любом Accept** (`handleAcceptIssue` → `setIssuePopover(null)`, VariantA.tsx:200-205), а его `issues` — статический снапшот с момента клика. «Принял одну — пересекающиеся исчезли из попапа» сегодня ненаблюдаемо в принципе.
3. **Одиночный Accept не инвалидирует перекрытых соседей**: они остаются `open` и видимыми, в `outdated` попадают только при собственной попытке применения (store.ts: applyIssueEdit трогает только свой issueId). Фильтр «прячем outdated» сам по себе не даёт владельческого «пересекающиеся пропадают».

## Решение

1. **Позиционирование**: мерить фактическую высоту попапа после рендера (`useLayoutEffect` + `getBoundingClientRect`) и репозиционировать; клامп top ≥ 8px. `max-height: 60vh` не трогаем (70vh из rev-1 отменён — не причина бага).
2. **Живой попап**: `issuePopover` хранит только якорь (paraId + ids); список карточек деривится из `paragraph.issues` стора по id на каждом рендере. Попап НЕ закрывается по Accept/Dismiss (закрытие — ✕, backdrop, смена абзаца). Принятая/устаревшая карточка выпадает из деривации сама.
3. **Серверная инвалидация перекрытий при apply** (амендмент non-goal rev-1 «не трогаем сервер» — verify-spec доказал, что без этого цель невыполнима): после успешного `_splice_suggestion` в apply-роуте пройтись по оставшимся `open`-issues абзаца тем же whitespace-толерантным матчером; фрагмент больше не находится → `status='outdated'`; обновлённые issues возвращаются в ответе apply, фронт вливает. Так пересекающиеся умирают в момент ПЕРВОГО принятия — и в попапе, и в инспекторе.
4. **Отображение**: `outdated` фильтруются из попапа и инспектора (в инспекторе `accepted`/`dismissed` остаются приглушёнными как история — новая трёхчастная таксономия фиксируется в webapp.md). `review-extension.ts:116` уже фильтрует не-open — код не трогаем, только регрессионный тест. `IssuesPanel.tsx` — мёртвый код (не импортируется), скоуп-нота «skip» (кандидат в легаси-чистку, отдельно от этой ветки).
5. Строка «Applied N · M outdated» остаётся (независимое состояние, по построению не задета).

## Не делаем

- Виртуализация списка; изменение семантики dismissed/accepted; восстановление dismissed (UI-аффорданса и сейчас нет).
- Не трогаем `review-extension.ts` (уже корректен) и `IssuesPanel.tsx` (мёртв).

## Критерии успеха

1. vitest: (а) новый негативный тест — issue со статусом `outdated` НЕ рендерит карточку ни в попапе, ни в инспекторе (существующих тестов «на приглушённую карточку» нет — пишем новые, не инвертируем); (б) попап остаётся открытым после Accept и теряет принятую карточку; (в) позиционирование — top ≥ 8 при высоком стеке (jsdom-уровень: клامп-функция как чистая юнит); (г) регрессия: underline-декорации не строятся для outdated.
2. pytest: apply инвалидирует перекрытые open-issues того же абзаца (exact + whitespace-случай не инвалидируется, т.к. применим), ответ несёт обновлённые статусы.
3. e2e: абзац с ≥5 issues — скролл, Accept одной → пересекающиеся исчезли из открытого попапа немедленно; скриншоты до/после.
4. Test-ids: `issue-popover` (контейнер-скролл), `inspector-issues-scroll`.
5. Doc-parity тем же коммитом: webapp.md (issue lifecycle: инвалидация при apply, трёхчастная видимость) + **known_issues.md:53** (устаревшая фраза «render dimmed with outdated label»).
