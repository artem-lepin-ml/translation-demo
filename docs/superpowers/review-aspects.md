# Review aspects — проектная адаптация

Up-link: [CLAUDE.md](../../CLAUDE.md) · [docs/README.md](../README.md). Канонический каталог, формат findings и правила агрегации — `~/.claude/skills/verify-spec/aspects-catalog.md` (единый источник истины). Здесь — проектная выборка + кастомы. Ручные правки владельца держать в блоках `<!-- custom -->`; при регенерации канонической части они переносятся без изменений.

**Severity:** CRITICAL — нарушение инварианта/цели, ломает базовый сценарий; HIGH — конфликт требований, непроверяемый критерий, дыра в безопасности/данных/деньгах; MEDIUM — дрейф терминологии, непокрытый edge-case, недоспецификация; LOW — стиль, мелкая избыточность. **Findings:** `{aspect, severity, confidence 0..1, evidence: цитата с path/line, fix: конкретное предложение}`. Пустой результат = явное «по этим проверенным пунктам находок нет».

## Канонические аспекты (выборка)

### 1. Цель и ограничения (always)
- **SPEC:** цель сформулирована как проверяемое состояние? Есть non-goals/скоуп? Три контрибьюшена демо (детерминированная терминология с Wikidata-грундингом; интерпретируемый разбор по кастомным критериям; end-to-end цикл улучшения) трассируются в контрактную поверхность? Нет частей цели без задач и ограничений без проверки?
- **PR:** каждый критерий успеха имеет исполняемую проверку; ни один инвариант CLAUDE.md не нарушен; каждый контрибьюшен демонстрируется в браузере.

### 3. Системный слой / контракты (≥2 модуля или новый контракт)
- **SPEC:** границы и владельцы (frontend / backend / term-агент / `LLMClient`) объявлены и через интерфейсы? Контракты на стыках полны и однозначны (вход/выход/коды)? Нет дублирования способностей (демо-клиент vs production-клиент; судейский `terminology` критерий vs Wikidata-слой)? DTO-заявления («схему не меняем») доказаны?
- **PR:** контракт совпадает с реализацией; модуль изолирован (general working rule 1 в `.claude/process.md`); ни один Hard Invariant из CLAUDE.md не нарушен.

### 4. Инженерный слой (есть исполняемый код)
- **SPEC:** абстракции оправданы, не спекулятивны? Ответственности не смешаны? Политика ошибок задана (сбой API, таймаут, невалидный JSON модели)? Observability — учёт токенов/стоимости на каждый вызов? Ретраи ограничены?
- **PR:** ошибки не глотаются молча; частичный сбой оценки не роняет весь `/evaluate`; логи достаточны для разбора.

### 5. Данные и хранилище (меняются схема/seed/сравнение)
- **SPEC:** SQLite-DDL непротиворечива? FK/идемпотентность/гонки при живом `/evaluate`? seed воспроизводим; reset-к-seed и кеш-фолбэк не ломают целостность? Метрики над данными (morph-key overlap и т.п.) определены однозначно и воспроизводимо?
- **PR:** миграции применяются на чистой БД; seed заполняет; reset возвращает к исходному; на реальном seed метрика считается.

### 6. Интерфейс (затрагивает фронт)
- **SPEC:** контракт даёт фронту всё для рендера (два сигнала терминологии, подчёркивания критериев, состояния цикла loading/`cached`/«до-после», reset, редактор гетерогенных `params`)? Экраны и стабильные test-id заданы? UX принятых issues при пересчёте?
- **PR:** ≥10 скриншотов, реальные сценарии, провенанс.

### 7. Документация (always)
- **SPEC:** doc-parity запланирован в том же коммите? Четырёхуровневое дерево соблюдено? Единый источник истины (контракты — в одном месте, остальные линкуют)? Up-link'и на месте?
- **PR:** доки обновлены вместе с кодом; ссылки живые; легаси помечено/убрано.

### 8. Операции и секреты (always before merge)
- **SPEC:** ключ хранится безопасно (`.env`, gitignore, secret-guard)? Ветка/PR по модели (`feat/*` от `dev-demo`)? Нет обхода хуков? Git-LFS для данных? Есть операционные свидетельства (лог прогонов)?
- **PR:** ключ не утёк в git/логи/ответы GET; прогон реального API оставил артефакты (JSONL со стоимостью); CI зелёный; прод-viewer жив.

## Проектные кастом-аспекты

### C1. Безопасность трат (реальный платный API)
- **SPEC:** есть жёсткий кумулятивный потолок ($2) с остановкой прогона? Учтён риск reasoning-токенов (скрытый биллинг как output)? `max_tokens` ограничен? Оценка стоимости до прогона? Нет слепых циклов/ретраев, способных слить бюджет? Лимит ключа ($3) как второй эшелон?
- **PR:** фактическая стоимость логируется из `usage` и сверяется; при достижении потолка прогон реально останавливается; ни один путь не делает неограниченное число вызовов.

### C2. Верность матрице параметров (провайдер-корректность)
- **SPEC:** для каждой модели шлются только поддерживаемые параметры (по живому каталогу)? `temperature` опускается там, где игнорится/запрещён? reasoning как `{effort}` vs `{max_tokens}` vs vLLM `enable_thinking` — верно на модель? Открытые вопросы вынесены на живой probe, а не зашиты догадкой?
- **PR:** pre-flight отбрасывает неподдерживаемые поля; live-probe закрыл открытые вопросы; ни одна модель не получает «мёртвый» параметр, поданный как живой.

### C3. Идиоматичность и скоуп (ethos проекта)
- **SPEC:** гибкость оправдана конкретными вызовами, а не «на будущее» (No speculative abstractions)? «Оживляем существующее», а не строим пререквизиты? Расширение UI — на существующих `va-*` токенах/классах?
- **PR:** нет неиспользуемых абстракций/полей конфига без конкретного потребителя; фронт не вводит новых токенов.

### C4. R&D / соответствие бизнес-видению (EMNLP demo-track)
- **SPEC:** контракты реально доставляют 3 контрибьюшена и историю demo-track? Контекстная дизамбигуация глоссария поддержана (`GlossaryEntry{term, context, …}` — омонимы И однофамильцы)? Два сигнала терминологии защитимы для статьи? Конфигурируемый судья даёт интерпретируемость и MQM-совместимый вывод?
- **PR:** на демо видно все 3 вклада; терминология различает омоним/однофамильца по контексту.

### C5. Целостность цикла улучшения и устойчивость на сцене
- **SPEC:** end-to-end `evaluate → apply-edit → re-score → прирост` когерентен? Принятые/отклонённые issues переживают пересчёт? Кеш-фолбэк и reset не дают рассинхрона состояния? Режимы отказа живого LLM-вызова на сцене закрыты?
- **PR:** реальный прогон цикла в браузере показывает прирост; обрыв сети → кеш-фолбэк срабатывает; reset чистит.

### C6. Граница term-агента (интеграция)
- **SPEC:** `Term[]` / `term_pairs.json` — единственная поверхность? Демо не лезет во внутренности агента и наоборот? Контракт самодостаточен для независимой параллельной разработки? Моки → реальные данные без смены контракта?
