# Терминологический словарь RU→EN: подготовка к research-запросу

Up-link: [docs/pipeline.md](../pipeline.md). Контекст по существующей инфраструктуре глоссария — [CLAUDE.md](../../CLAUDE.md) (раздел Hard Invariants #8).

Документ собирает контекст по будущей стадии — построение словаря для post-edit замены терминов в черновике перевода. Реализация не описана; здесь — структуризация источника и подготовленный запрос для Claude UI / research mode.

## 1. Где мы в пайплайне

Сейчас работают:
- **Stage 02 — Translate**: черновики переводов на разных моделях и стратегиях чанкинга, артефакты в `data/pilot/translating/`.
- **Stage 03 — Scoring**: оценка переводов по 5 критериям + опциональный factcheck (`gpt-5.5-low` как baseline-судья).

Терминологический словарь — это **новая стадия пост-обработки** (после Stage 02, параллельно/перед Stage 03):
1. На входе — черновик перевода `translation.md` и словарь RU→EN.
2. На выходе — `translation.md` с заменёнными терминами и метаданные о замене (паттерн → совпадение → выбранный вариант).

В CLAUDE.md уже зафиксировано: `glossary/main.json` — single source of truth, Stage 3 читает и пишет через `Glossary.upsert`. Реальной реализации пока нет (директория `glossary/` отсутствует, `Glossary` класса в коде нет) — описан как контракт.

Параллельно — метрика «доля корректных терминов **без** словаря» как baseline для research-замера улучшения от словаря.

## 2. Источник для первичного наполнения

Том I, `data/raw/vol01_source.pdf`. Три блока в конце книги дают почти готовый seed-список русских терминов:

| Страницы | Блок | Что содержит | Структура |
|---|---|---|---|
| 774–795 | Хронологический указатель | Династии Египта, Месопотамии, античного мира + ключевые события (битвы, войны, реформы, договоры) с датами | Двухколоночная: левая колонка — термин/событие, правая — даты. Иерархия через отступы (династия → правитель → событие в правление). |
| 796–800 | Избранная литература | Источники, использованные авторами тома | Список ссылок, **не** глоссарий — игнорируем для seed, но полезно для cross-validation. |
| 801–832 | Указатель имён | Все имена собственные с номерами страниц упоминания | Алфавитный список: имя + страницы, иногда с альтернативами и пояснениями. |

### Типы сущностей в этих блоках

Из скринов видно как минимум:

- **Правители** с эпитетом-троном в скобках: «Аменхотеп IV (Эхнатон) (Неферхепрура-уаенра)», «Тутмос III (Менхеперра)», «Рамсес II (Усермаатра Сетепенра)».
- **Альтернативные имена / синонимы** через `=` или `/`: «Нармер (= Мина)», «Небра/Ранеб», «Хэйлунцзян, р.; см. также Амур».
- **Династии** римскими цифрами: «XVIII династия», «I династия Киша».
- **Топонимы с дизамбигуацией**: «Фивы (в Египте)» vs «Фивы (в Греции)».
- **События**: «Битва при Кадеше», «I хетто-египетская война», «Реформы Солона в Афинах».
- **Археологические культуры / периоды**: «Бадари», «Накада II (герзейская)», «Эпоха Эреду», «Латенский период».
- **Народы и племенные союзы**: «дако-гетский племенной союз Буребисты», «„народы моря“».
- **Институты / своды**: «Эдикт Каракаллы», «Законы XII таблиц», «Пелопоннесский союз».
- **Географические объекты с указанием типа**: «о-в Фасос», «п-ов Халкидика», «р. Хуанхэ», «оазис Харга», «зал. Ханчжоувань».
- **Сноски с „средней“ хронологией** — вариант датировки в скобках под основной таблицей: для словаря не нужно, но парсер должен это уметь пропускать.

### Сложности парсинга

- Двухколоночная вёрстка с переменным отступом — это **не таблица**, а позиционный текст с табуляцией.
- Скобки несут разную семантику: тронный эпитет, альтернативное имя, тип объекта (царица, архитектор), уточнение скоупа («в Египте»), маркер сомнения «(?)».
- Пометки в квадратных скобках: «Мернейт [царица]», «Таусрет (Сатрамеритамон) [царица]».
- В указателе имён номера страниц склеены с именем и идут диапазонами и через запятую: «Августин Блаженный 664, 687, 690–693, 701».
- Часть позиций — это перекрёстные ссылки («см. также…», «см.»), а не самостоятельные термины.

## 3. Что хотим получить как минимум — формат словаря

Предложение до research-фазы, чтобы было от чего отталкиваться. Финал — после запроса в Claude UI.

```jsonc
// glossary/main.json — список объектов, один на «понятие»
{
  "id": "amenhotep-iv",                  // стабильный slug
  "ru": {
    "lemma": "Аменхотеп IV",             // словарная форма
    "aliases": ["Эхнатон"],              // тронные имена, альтернативы
    "throne_name": "Неферхепрура-уаенра" // опционально
  },
  "en": {
    "primary": "Akhenaten",              // выбранный английский эквивалент
    "alternatives": ["Amenhotep IV", "Amenophis IV"],
    "source": "wikipedia:en:Akhenaten",  // откуда взяли — Wikipedia/Wikidata/manual
    "confidence": "high"
  },
  "category": "ruler",                   // ruler/dynasty/place/event/culture/people/...
  "scope": "egypt-18-dyn",               // дизамбигуация (Фивы EG vs GR)
  "notes": "Также: Amenophis IV в немецкоязычной традиции"
}
```

Ключевые требования к формату:
- Поддержка нескольких форм русского написания (для лемматизации/морфоанализа на стадии замены в переводе).
- Поддержка нескольких допустимых английских вариантов с явно выбранным primary.
- Источник перевода и confidence — для дальнейшего ручного аудита и для расчёта метрики покрытия.
- Категория и скоуп — чтобы при замене не путать одноимённые сущности.

## 4. Алгоритм построения и использования (из задания)

1. Договориться о формате и интерфейсе словаря и алгоритме его наполнения.
2. Распарсить страницы 774–832 → seed-список русских терминов с категориями.
3. Перевести часть автоматически через Wikipedia: если у русской статьи есть interwiki-ссылка на английскую — берём заголовок английской статьи как primary, остальные redirects как alternatives.
4. (*) Попробовать второй автоматический источник: если русская историческая монография имеет английский перевод, вытащить термины через выравнивание параллельного корпуса.
5. На стадии корректировки черновика: морфоанализ русского перевода-источника → matching по русским леммам словаря → замена в английском черновике на primary вариант.

Метрика прогресса — `terminology_coverage_at_source` (доля терминов из словаря, найденных в русском оригинале) и `terminology_correct_in_draft` (доля терминов, которые модель **уже** перевела корректно без словаря, измеряется как exact-match `primary` или попадание в `alternatives`).

## 5. Запрос для Claude UI (research mode)

Ниже — самодостаточный prompt, копировать целиком. Цель — узкая выжимка по существующим решениям, а не литобзор.

---

**Контекст.** Я строю систему перевода русскоязычной академической исторической энциклопедии («Большая советская энциклопедия», 7 томов) на английский в академическом регистре. Черновик делается LLM-ом (frontier и open-source модели в сравнении). Главная боль — корректный перевод **исторических терминов и имён собственных**: фараонов, царей, династий, городов, битв, культур, договоров. Стандартный машинный перевод транслитерирует фонетически («Tutmos», «Hatshepsut», «Hammurapi»), а в академической английской литературе закреплены другие нормы («Thutmose / Thutmosis», «Hatshepsut», «Hammurabi») — иногда с несколькими допустимыми вариантами и явным primary.

**Что у меня уже есть.**
- Seed-источник на ~2000–3000 русских терминов: chronological index + name index из самой книги (страницы 774–832).
- Категории сущностей: правители, династии, топонимы, события (битвы/войны/договоры), культуры/периоды, народы, своды законов, географические объекты.
- Доменная специфика: Древний Египет, Месопотамия (Шумер/Аккад/Вавилония/Ассирия), античная Греция и Рим, Древний Китай, Древняя Индия — для каждого региона у academic English есть устоявшаяся школа транслитерации (Egyptology: Allen/Gardiner; Assyriology; Sinology: Pinyin vs Wade-Giles).
- Доступ к LLM (OpenAI/Anthropic/Google/open-source), Wikipedia/Wikidata API, потенциально — параллельные корпуса русских исторических монографий с английским переводом.

**Что я хочу узнать. Дайте конкретные ответы по каждому пункту — с названиями инструментов/библиотек/методов и ссылками на работы/репозитории, без воды.**

1. **State-of-the-art подходы к построению bilingual glossary для named entities в специализированном домене (history/archaeology).** Какие пайплайны действительно работают на практике? Кто решал близкую задачу (классика, египтология, синология)?

2. **Cross-lingual entity linking через Wikipedia / Wikidata.** Какие готовые библиотеки/сервисы дают по русскому термину английский эквивалент с указанием confidence и альтернатив? Конкретно интересует: `wikimapper`, `mwparserfromhell`, `wikidata-cli`, `OpenTapioca`, `BLINK`, `mGENRE`, `ReFinED` — что из этого живо, что из этого подходит для исторических имён собственных, какие подводные камни (например, отсутствие redirect-ов, polysemy)? Альтернативы и более новые проекты тоже интересны.

3. **Multi-variant transliteration disambiguation.** Когда в английской литературе для одного русского имени есть несколько норм (Thutmose / Thutmosis / Tuthmosis; Akhenaten / Echnaton / Ikhnaton; Cheops / Khufu), как выбирать primary? Есть ли подходы на основе частотности в корпусах (Google Books n-grams, JSTOR, специализированные корпуса) или на основе авторитетных reference works (Cambridge Ancient History, Oxford Encyclopedia of Ancient Egypt)? Какие конкретно ресурсы пригодны для programmatic lookup?

4. **Terminology-constrained machine translation / post-editing.** Какие есть подходы для **навязывания** глоссария уже сделанному LLM-переводу? Простая regex-замена по леммам vs более умные подходы (constrained decoding, terminology injection в prompt, post-edit модель). Есть ли open-source инструменты — `dictionary-based post-editing`, `OpusMT terminology constraints`, `NLLB terminology`, что-то ещё? Сравнительные оценки качества.

5. **Морфологический анализ русского для matching по словарю.** Русские термины в тексте встречаются во всех падежах и числах. Какой стек лучше для лемматизации в исторических текстах с большим количеством редких имён собственных: `pymorphy2/3`, `natasha`, `spacy-ru`, `udpipe`, `stanza`, LLM-based NER? Особенно интересует обработка незнакомых лемм («Хетепсехемуи», «Мескиаггашер»).

6. **Существующие RU↔EN ресурсы по исторической терминологии.** Есть ли готовые открытые глоссарии (от ЮНЕСКО, академических библиотек, Wikidata properties, OpenHistoricalMap, Pleiades для античной географии)? Существуют ли parallel corpora русских исторических монографий с published English translations, из которых можно вытащить термины автоматически (например, через `awesome-align`, `SimAlign`, `eflomal`)?

7. **LLM-as-glossary-builder практики.** Современные подходы используют LLM напрямую для построения глоссария (по prompt'у с retrieval над авторитетными англоязычными источниками). Какие best practices, какие провалы? Есть ли работы, оценивающие надёжность LLM для перевода исторических имён собственных (особенно — frontier vs специализированный fine-tune)?

8. **Quality validation / human-in-the-loop.** Какие workflow приняты для валидации построенного словаря экспертами (в моём случае — кафедра всеобщей истории МГИМО)? UI-инструменты, форматы ревью, метрики согласия между ревьюерами на терминологических решениях?

**Чего не нужно.**
- Общих обзоров «что такое NER» или «что такое cross-lingual word embeddings».
- Списка из 50 paper'ов «по теме» без фильтрации.
- Решений, требующих обучения большой собственной модели с нуля.
- Коммерческих SaaS без open-source альтернатив (если только это не безусловный SOTA с конкретной оценкой).

**Что нужно на выходе.** Структурированный ответ по 8 пунктам выше, в каждом: 2–4 конкретных инструмента/работы/подхода с краткой оценкой применимости к моей задаче, ссылками и одним-двумя предложениями про подводные камни. Финальный раздел — рекомендуемая комбинация для MVP (Wikipedia → fallback на LLM → human review) с обоснованием.
