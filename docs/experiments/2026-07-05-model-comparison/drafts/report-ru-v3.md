# Оценка извлечения терминологии и Wikidata-grounding на разметке Википедии: отчёт об эксперименте

**Дата:** 2026-07-06, версия 4. **Статус:** прогоны двух моделей и ablation завершены. P_label получен для этих двух моделей. Прогон третьей модели (qwen3.7-plus) инвалидирован из-за нестабильности провайдера. Чистый перезапуск в очереди (см. § 3.8). gpt-5.5 исключён из эксперимента: за весь период не нашлось стабильного маршрута через шлюз (429). **Воспроизводимость:** все числа берутся из закоммиченных `metrics.json` в ветке эксперимента.

## 1. Резюме

Мы измеряем пайплайн «NER-извлечение терминов → Wikidata-grounding (G6 label_first)» на эталонной разметке из внутренних ссылок 100 статей русской Википедии по древней истории. Эталон содержит 7 959 упоминаний и 3 868 уникальных QID. Основная метрика **R_doc (Document-level Recall)**: сравниваются списки QID документа. Эталонное упоминание засчитано, если его QID предсказан где-либо в той же статье.

**Главный результат.** gemini-3.1-flash-lite: R_doc = 0.690 [0.680–0.700]. deepseek-v4-flash: R_doc = 0.614 [0.604–0.625]. Precision (нижняя граница): P_mention ≈ 0.30, P_type ≈ 0.45 у обеих моделей.

**Главный аналитический вывод.** Recall раскладывается в произведение покрытия извлечения и точности grounding при найденном упоминании. Точность grounding у моделей одинакова (0.814 против 0.815). Вся разница создаётся покрытием NER-стадии (0.763 против 0.632). Grounding при найденном упоминании близок к насыщению, 0.85–0.93 на успешных путях разрешения. Резерв роста находится в извлечении, прежде всего нарицательной терминологии: R_doc именованных сущностей 0.828, нарицательных 0.414. Этот разрыв мотивировал ярусные метрики recall, см. § 3.6.

## 2. Методология

### 2.1 Корпус

100 статей, 10 фиксированных тематических секций древней истории (Шумер, Египет, Ассирия, Хеттское царство, Финикия, Ахеменидский Иран, Индия, Китай, Греция, Рим), по 10 статей на секцию. Отбор в каждой секции детерминирован:

1. **Пул**: все статьи подкатегорий секции, только основное пространство имён. Статья из нескольких секций закрепляется за первой по фиксированному порядку и используется один раз.
2. **Перемешивание** пула с seed = 42.
3. **Последовательный обход** с гейтом на каждом кандидате: не меньше 30 уникальных внутренних ссылок в тексте, самая ранняя дата Wikidata-сущности раньше 500 г. н. э. (сущности без дат сохраняются), блэклист типов P31 (фильм, картина, музей).
4. **Остановка после 10 принятых**.

Фильтр применяется в ходе случайного обхода, поэтому корпус содержит ровно 100 статей по построению. Категоризация Википедии шумная. Примерно 3 статьи из 100 выходят за целевой период, они сохранены и задекларированы. Число эталонных упоминаний среза обозначается в таблицах как Gold mentions, например у секции greece это 1 506.

### 2.2 Эталонная разметка: ссылка → QID

Эталон строится из разметки, которую сообщество Википедии уже сделало руками, то есть из внутренних ссылок:

1. **Источник.** Из HTML-снапшота статьи берутся внутренние ссылки основного пространства имён из абзацев текста. Навигационные блоки, инфобоксы и сноски не участвуют.
2. **Разрешение цели.** Заголовок целевой страницы детерминированно отображается в QID через MediaWiki API (`pageprops.wikibase_item`) с прохождением цепочек перенаправлений. LLM на этом этапе не используется.
3. **Хронологический фильтр.** Цели-хронемы (годы, века, десятилетия по типу P31) исключаются. Ссылка на «612 год до н. э.» размечает навигацию по времени, а не терминологию.
4. **Эталонное упоминание.** Каждая оставшаяся ссылка даёт запись (индекс токена, поверхность, QID, длина спана) на едином токенном потоке статьи.

HTML-снапшоты статей и версия хронологического набора фиксируются в записях эталона, поэтому сборка воспроизводима. *Технические отказы учитываются счётчиками в метаданных сборки.*

Воронка корпуса: 8 829 внутренних ссылок → 405 исключено хронофильтром → 6 без Wikidata-элемента → 7 959 эталонных упоминаний, 3 868 уникальных QID.

### 2.3 Метрики

**Recall как основная ось.** Эталонная разметка точна, но неполна. По редакционной политике размечается, как правило, только первое упоминание сущности (DaMuEL: «Wikipedia documents deliberately annotate only a single mention for every entity present»). Отсутствие ссылки не означает «не термин». Поэтому recall по такой разметке честен, а precision является только консервативной нижней границей.

Режимы сопоставления, от основного к вспомогательным:

- **R_doc, Document-level Recall (основной)**: сравнение списков QID. Эталонное упоминание засчитано, если его QID предсказан где-либо в той же статье. Сопоставление всегда внутри одной статьи.
- **R_span, Span-overlap Recall**: токенные спаны пересекаются и QID совпадает.
- **R_strict, Strict-match Recall**: совпадают индекс первого токена, нормализованная поверхность и QID. Заведомо заниженная оценка, чувствительная к границам многословных упоминаний.

Инвариант R_strict ≤ R_span ≤ R_doc выполняется во всех прогонах. Таблица трёх режимов приведена в § 3.2, остальные таблицы используют R_doc.

**Precision (нижняя граница, позиционное сопоставление по пересечению спанов):**

- **P_mention, Mention-level Precision**: доля совпавших с эталоном среди всех предсказанных упоминаний с QID.
- **P_type, Type-level Precision**: то же после дедупликации предсказаний по паре (поверхность, QID). Компенсирует конвенцию «повторы не размечаются». Разрыв P_type − P_mention прямо измеряет эту конвенцию.
- **P_label, Label-verified Precision**: предсказание вне эталона дополнительно засчитывается, если его поверхность существует как метка Wikidata. На детерминированном пути exact_label поверхность совпадает с меткой по построению, там P_label тавтологично равен 1. Поэтому P_label считается без этого пути. Значения приведены в § 3.7.

**Ярусные метрики recall.** Разрыв между именованными и нарицательными поставил вопрос о шуме в самом эталоне. Введены три вложенных детерминированных яруса фильтрации эталона по типу целевой сущности (P31 целевого QID):

- **R_all**: весь эталон, совпадает с R_doc.
- **R_clean**: исключены цели со структурным шумом. Это служебные страницы (дизамбиги, списки, категории) и календарные сущности, пережившие хронофильтр.
- **R_term**: дополнительно исключены общесловарные внедоменные классы. Это языки и системы письма, биологические таксоны, материалы, единицы измерения, академические дисциплины и абстрактные мета-темы. Доменные понятия (зиккурат, папирус, династия, титул, божество, этнос) сохраняются.

Проверенная и отклонённая альтернатива: оставлять только сущности с координатами, датами или типом «человек». Такое правило выбрасывает 30 % эталона вместе с корректно находимой доменной терминологией и даёт recall нарицательных ниже, чем R_term. Оно режет сигнал, а не шум.

Каждая ячейка таблиц сопровождается 95%-ным доверительным интервалом Уилсона. Ячейки с числом упоминаний меньше 30 помечаются и не интерпретируются.

### 2.4 Измеряемая система: G6 label_first

Пайплайн для каждого упоминания (поверхность и лемма приходят с NER-этапа) показан на рис. 1 (файл `g6-pipeline.png`):

1. **Лестница кандидатов**: поиск по лемме, затем по поверхности. При нуле кандидатов полнотекстовый поиск. Пустая лестница даёт исход `no_candidates`.
2. **Точное совпадение**: сначала по русской метке кандидата, при промахе по алиасам.
3. **Решение**: ровно одно точное совпадение даёт детерминированный исход `exact_label` без вызова LLM. Иначе LLM-судья обязан выбрать из предъявленных кандидатов или отказаться. Валидный выбор даёт `llm_disambiguation`, явный отказ `judge_rejected`, сбой или невалидный ответ `judge_unavailable`. Подстановка топ-1 кандидата исключена по построению.

*Ступень «заголовок Википедии → sitelink», ранее замыкавшая лестницу, отключена в оценочных прогонах из-за обнаруженной циркулярности с механизмом разметки, см. § 5.*

Три улучшения лестницы в формате «ломающийся пример → механизм → вклад». Вклады даёт leave-one-in ablation на 20-статейном подмножестве корпуса (1 443 упоминания, R_span), в скобках независимый контрольный набор из 91 термина:

1. **Поиск по лемме.** Ломается: косвенная форма «Саргона» промахивается мимо префиксного поиска по метке «Саргон». Механизм: NER-этап отдаёт лемму, поиск по ней идёт первым. Вклад **+0.322** (+0.318).
2. **Полнотекстовый фолбэк.** Ломается: термин недостижим префиксным поиском, ноль кандидатов, судья не вызывается. Механизм: при нуле кандидатов запускается полнотекстовый поиск. Вклад **+0.145** (+0.142).
3. **Совпадение по алиасам.** Ломается: у кандидата основная метка «Sargon of Akkad», русский вариант лежит в алиасах, точного совпадения нет, лишняя эскалация к судье. Механизм: при промахе метки проверяются алиасы. Вклад **+0.004** (+0.000). Точность не меняет, сохранён ради прозрачности трассы решения.

Полная сетка конфигураций приведена в § 3.5.

### 2.5 Постановка эксперимента

Модель-кандидат занимает обе LLM-роли, извлечение и судейство, и измеряется как полная замена в пайплайне. Конфигурация лестницы фиксирована. *Для устойчивости к сбоям внешних API реализованы: ограниченные повторы транзиентных ошибок с паузами по `Retry-After`, освобождение слота параллелизма на время паузы, пер-статейное сохранение промежуточных результатов с возобновлением, бюджетное резервирование перед каждым вызовом, счётчики всех отказов в метаданных прогона.*

Масштаб одного полного прогона: 2 644 вызова извлечения (по одному на абзац), примерно 5 тысяч вызовов судьи, примерно 20–25 тысяч уникальных обращений к Wikidata и Wikipedia API (поиск кандидатов, метки, перенаправления, всё кэшируется). Обращения к Wikidata ограничены вежливостью клиента: 2–3 одновременных запроса, паузы при 429. Эта часть занимает по оценке 1.5–3 часа на прогон при холодном кэше и минуты при прогретом. *Точные счётчики обращений добавлены в метаданные начиная с текущего прогона.*

Принят строгий вариант яруса.*

### 3.7 P_label

P_label досчитан для двух завершённых моделей, без тавтологичного пути exact_label. gemini-3.1-flash-lite: P_label = 0.526. deepseek-v4-flash: P_label = 0.530. Значения выше P_type (0.451 и 0.458) примерно на 7 п. п. и почти не различают модели, тот же паттерн, что и у точности grounding в § 3.3.

### 3.8 Надёжность провайдеров как фактор валидности

Прогон qwen3.7-plus в ночь на 2026-07-06 совпал с волной 429-ошибок на стороне провайдера qwen (provider-8). Прогон использует уже описанный в § 2.5 механизм пер-статейного сохранения с возобновлением. Журнал прогресса этого механизма показывал 99 из 100 статей выполненными, но файл предсказаний фактически содержал данные только по 36 статьям. Извлечения молча терялись, а статьи при этом помечались как готовые. Это рассинхрон между журналом прогресса и файлом предсказаний, заведён как отдельный баг пайплайна. Сегодняшнее возобновление прогона довосстановило 29 статей, которые механизм смог распознать как пропущенные. Ещё 35 статей остались ложно помеченными «готово». В итоге финальные предсказания реально покрывают только 65 из 100 статей. Во время сегодняшнего повторного grounding по этим статьям те же 429-ошибки задели вызовы судьи, той же модели qwen. Исход `judge_unavailable` получили 735 предсказаний у qwen против 12 у gemini.

Несколько независимых признаков указывают на инфраструктурную причину, а не на качество модели. Число предсказаний на статью повторяет хронологию отказа. У первых 30 обработанных статей в среднем 39.6 предсказаний на статью, у последних 30, обработанных уже после стабилизации маршрута, 136.9. Статья «Яффа», целиком обработанная сегодня, дала 1 168 предсказаний. Это больше, чем 1 044 у gemini на той же статье. Там, где маршрут к провайдеру не был повреждён, qwen извлекает не хуже gemini и даже богаче. Форензический R_doc по сохранившимся предсказаниям qwen равен 0.164, при этом точность по стратам 0.87–0.98. Там, где модель успела отработать, она точна. Итоговый recall занижен пропущенным покрытием, а не качеством модели.

По той же причине из сравнения исключён gpt-5.5. За всё время эксперимента не нашлось стабильного маршрута через шлюз. И provider-8, и режим auto возвращали 429 от OpenAI начиная с 2026-07-05 23:20Z. Повторная проверка часом непрерывного пробинга 2026-07-06 15:41Z подтвердила то же самое. Оба случая, qwen и gpt-5.5, это один и тот же вывод эксперимента. Инфраструктурная нестабильность провайдера может молча исказить eval-данные так, что отказ маршрута будет выглядеть как слабость модели. Перед публикацией чисел нужен integrity-гейт: минимальная полнота покрытия статей и предельная доля `judge_unavailable`. Числа вне порога помечаются как невалидные для сравнения моделей, как сделано здесь для qwen. Чистый перезапуск qwen3.7-plus поставлен в очередь за вотчером маршрута и стартует, как только qwen@provider-8 перестанет отдавать 429.

## 4. Сопоставление с литературой

Прямого аналога нашей постановки (русский язык, историческая терминология, эталон из ссылок Википедии, уровень QID) в литературе нет. В стандартной линейке многоязычного entity linking русский отсутствует.

- **Методологический прецедент.** Mewsli-9 («Entity Linking in 100 Languages», Botha et al., EMNLP 2020) строит эталон так же: тексты ссылок как упоминания, разрешённые в Wikidata. Supervised-модели достигают 0.89–0.90 R@1, mGENRE (TACL 2022) даёт 90.2 micro-accuracy. Обе обучены на миллионах таких же ссылок и не покрывают русский. Наш пайплайн без обучения на разметке даёт 0.69 document-level recall при 0.81 точности grounding. Это позиция zero-shot системы на непокрытом языке.
- **Неполнота разметки** (обоснование recall-primary): DaMuEL (2023) фиксирует политику «одна ссылка на сущность», Gerlach et al. (2021) разреженность ссылок между языковыми разделами. Поэтому P_type поднимает нижнюю границу precision с 0.30 до 0.45, количественно показывая вклад конвенции.
- **Контекст end-to-end EL.** GENRE (ICLR 2021) на курируемом английском AIDA даёт 83.7 micro-F1. Сравнение лоб-в-лоб некорректно: F1 против recall на неполном эталоне, другой язык и домен.
- **KG-MT** (Conia et al., EMNLP 2024, Outstanding Paper) оценивает retrieval сущностей из Wikidata только сквозь качество перевода (метрика M-ETA, +129 % и +62 % к NLLB-200 и GPT-4). **SemEval-2025 Task 2 (EA-MT)** институционализирует перевод с Wikidata-сущностями (лучшая система без данных ID даёт M-ETA 71.7). Наш вклад комплементарен: прямое воспроизводимое измерение самой стадии «найти и привязать» на человеческой разметке.

## 5. Эволюция методологии

Путь решений, объясняющий текущий дизайн:

1. **Корпус v1 → v2.** Исходная стратификация «50 сложных / 50 типичных» по ambiguity-скору отменена в пользу 10 тематических секций. Секции проще аудировать, и они дают срез стабильности по субдоменам.
2. **Основная метрика: от позиционной к документной.** Позиционное сопоставление переносит в метрику шум границ и токенизации. Документное сравнение списков QID прозрачнее формулирует целевую задачу и выбрано основным. Позиционные режимы сохранены как ablation строгости. *(Историческое соответствие внутренних кодов: M1 = R_strict, M2 = R_span, M3 = R_doc, P1 = P_mention, P2 = P_type, P3 = P_label.)*
3. **Разрыв именованных и нарицательных → ярусные метрики.** Аномально низкий recall нарицательных поставил вопрос о шуме эталона. Ответ: детерминированные ярусы фильтрации по типу целевого QID и разбор состава промахов (34 % шум, 66 % настоящие пропуски).
4. **P_label: от заглушки к активации.** В первых прогонах предикат существования метки не был подключён. Теперь P_label считается по-настоящему и репортится без тавтологичного пути exact_label.
5. **Обнаруженная и устранённая циркулярность.** Последняя ступень лестницы кандидатов (заголовок Википедии → sitelink → QID) воспроизводила механизм построения эталона. Детерминированный реплей из кэшей прогонов дал точную оценку: 1.0–1.2 % граунд-предсказаний, эффект 0.5–0.8 п. п. recall, ранжирование моделей не затронуто. Совпадение с эталоном у этой ступени 52–60 % при её доле объёма 1 %, что сильно выше случайного уровня и подтверждает циркулярность. Ступень отключена в оценочных прогонах (отдельный тумблер `use_sitelink`), в отчёт идут обе версии чисел. В каталог ревью-аспектов добавлен класс «annotation-mechanism leakage».
6. **Инженерная устойчивость.** Ранние прогоны выявили три класса сбоев внешних API. Ответ: механизмы из § 2.5. После них прогоны воспроизводимо доходят до конца.

## 6. Ограничения и следующие шаги

**Ограничения.** Шумная категоризация Википедии (около 3 % статей вне периода, задекларированы). Неполнота эталонной разметки, поэтому precision только нижняя граница. Тип упоминания определяется капитализацией поверхности. Сравнение deepseek включает 4.1 % потерянного покрытия из-за отказов API (задекларировано, поправка приведена). Недетерминизм LLM-судьи ограничен фиксацией temperature = 0.

**Следующие шаги.** Чистый перезапуск qwen3.7-plus и досчёт P_label для третьей модели, как только маршрут к провайдеру стабилизируется (см. § 3.8). Повторная попытка подключить gpt-5.5, если у шлюза появится стабильный маршрут. Integrity-гейт перед публикацией чисел моделей: минимальная полнота покрытия статей и предельная доля `judge_unavailable`. Чистые числа без sitelink-ступени для всех трёх моделей. Кросс-табуляция типов эталона с категориями экстрактора. Расширение корпуса на второй домен для проверки переносимости гейта отбора.
