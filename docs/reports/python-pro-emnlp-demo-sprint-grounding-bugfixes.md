# python-pro report: terminology/grounding bug fixes (EMNLP demo sprint)

## Scope

Implement two confirmed-CRITICAL grounding bugs found by the e2e campaign, plus one small NER-prompt fix, in the terminology/grounding pipeline:

- **FIX 1** — "one sense per discourse" judge cache was document-scoped in the live pipeline (`scope_id=doc_id`), so a document containing two distinct referents sharing the same lemma (e.g. Egyptian «Фивы» in one paragraph, Greek «Фивы» in another) let the second paragraph silently replay the first paragraph's judge decision (wrong QID, alien justification). Fix: scope the cache per paragraph.
- **FIX 2** — false-green via a single exact label/alias match with no judge veto: a namesake sharing an exact ru label/alias with the real referent (e.g. a TV series titled «Династия Цинь» vs. the real Qin dynasty labelled «Цинь»; «сирийских» exact-aliasing Q33538 Syriac language) auto-greened without ever consulting the judge, even when a genuine competing candidate sat in the same list. Fix: add a `confirm_exact` judge-veto toggle.
- **FIX 3** (small) — the NER lemma-extraction prompt was Russian-tuned; on Chinese source text the model emitted a Russian lemma, which then drove ru-label exact-match search straight into the FIX-2 namesake. Fix: add an explicit "lemma stays in the source language/script" instruction to the prompt.

## Decisions & rationale

- **FIX 1 scope tuple.** `pipeline.run()` is already called once per paragraph inside `_run`'s loop, and the paragraph id (`p["id"]`) is directly in scope there — no need to thread a mention→paragraph mapping through `TermMention`. Kept the single shared `judge_cache` dict (per spec instruction): only the key's scope component now varies per paragraph, so same-paragraph reuse (the «Хана»-twice-in-one-¶ case) still works, cross-paragraph reuse is cut off.
- **FIX 2 control flow.** Implemented the veto as a local closure `_exact_green()` defined inside the `if len(exact_matches) == 1:` block, capturing `chosen`/`candidates`/etc. from the enclosing `ground()` call. This closure is reused both for the "veto doesn't apply" early return and for every "judge unavailable/error" fallback point (exception, malformed response, qid-outside-candidate-set) — guaranteeing byte-identical output (including `judge_trace=None` and no cache write) to the flag being off, exactly matching the "availability must not regress" requirement.
- **No caching of judge-failure fallbacks.** Chose NOT to write a decision to `judge_cache` when the veto's judge call technically fails (exception/malformed/contract violation) — this mirrors the pre-existing deterministic-green path, which never touches the cache either (the early return happens before `cache_key` is computed). A transient failure therefore doesn't get "locked in"; the next call in the same scope simply retries the judge.
- **Cache shape reuse.** Reused the exact same `decision = {"resolved_by", "chosen_qid", "judge_trace"}` dict shape already used by `llm_disambiguation`/`judge_rejected`/`judge_unavailable`, just with `resolved_by="exact_label"` for a confirmed match. This kept `_from_cached_decision` a small, symmetric addition rather than a new data shape.
- **FIX 3 scope.** Added a single new bullet to the NER prompt rather than restructuring the existing nominative-case bullet, to keep the diff minimal and the "FROZEN"/owner-approval markers intact for the frozen-prompt tests.
- **Test fixture choice for FIX 2.** Built a dedicated `_namesake_confirm_wd()`/`_namesake_mention()` fixture modeling the «династия Цинь» prod case (exact ru-label namesake vs. a same-search-hit competitor with a *different* label) rather than reusing the existing `_khana_escalation_wd` fixture, because that one produces 2 exact matches (both candidates share the same label), which already escalates via the pre-existing `>=2 exact matches` path — it can't exercise the new `len(exact_matches) == 1` veto branch.
- **Live regression test for FIX 1.** Used 2 candidates that both exact-match the lemma («Фивы»/«Фивы») so the test exercises the ordinary `≥2 exact matches` escalation path (independent of `confirm_exact`), keeping the test a clean, single-variable regression check for the cache-scope fix rather than conflating it with the FIX 2 veto.
