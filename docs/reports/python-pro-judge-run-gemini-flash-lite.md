## Decisions & rationale

**Router ID.** `docs/experiments/2026-07-08-judge-probe/raw/models_catalog_subset.json`
only covers the 4 originally-probed models (no flash-lite). Queried the live
catalog (`GET {OPENROUTER_BASE_URL}/models`) directly: confirmed
`google/gemini-3.1-flash-lite` exists exactly as named (alias
`google/gemini-3.1-flash-lite-preview`), pricing $0.15/$0.45 per Mtok
in/out (vs. $0.825/$2.475 for `gemini-3.1-pro-preview`) — roughly 5.5x/5.5x
cheaper.

**Smoke test (4 direct HTTP calls, outside the runner, before touching any
config).** Using a real paragraph pair (id=72, `qwen-27b-bouquet-refined`,
accuracy criterion) and a second one (id=178, `translate-gemma-bouquet`,
style criterion):
1. `response_format=json_object`, no `temperature`/`reasoning` key: **200
   OK**, clean JSON, `reasoning_tokens=0`, latency 2.8s, cost $0.00019.
2. No `response_format`, prompt-only JSON: **200 OK**, clean JSON,
   `reasoning_tokens=0`, latency 4.8s, cost $0.000182.
3. Explicit `reasoning: {enabled: true}`, no `response_format`: **200 OK**,
   but reasoning actually engages (1371 reasoning tokens), latency triples
   to 13.7s.
4. Second sample (style/id178, with `response_format`): 200 OK, clean JSON,
   `reasoning_tokens=0`, latency 4.3s, cost $0.000254.

Conclusion: unlike `gemini-3.1-pro-preview` (which 400s on
`response_format=json_object` and reasons regardless of the parameter),
`gemini-3.1-flash-lite` on this route (a) accepts `response_format=
json_object` cleanly, and (b) reasons OFF by default unless explicitly
asked. This is exactly "vendor-default reasoning/effort" per the
coordinator's instruction — but no existing regime in the runner sends
*neither* `temperature` *nor* `reasoning`, so a new regime (`vendor_default`)
was added to `scripts/bouquet_judge_rerun.py` (additive-only, verified not
to disturb the other 3 judges' regimes; see the earlier interim version of
this report for the full considered-alternatives discussion). Held for the
whole 2376-call run: **0 reasoning tokens across every single row.**

**Pilot gate result: PASS.** `--pilot 20` (240 calls) → 240/240 scored, 0
parse failures. Failure rate **0.00%** (≤2% required), valid-score share

**Full run:** launched immediately after the gate passed, resumed from the

**Reading:** enabling reasoning made the judge uniformly **more generous**
(every mean score is higher, every tie-rate is higher — style moved the
most, +14.3pp on tie-rate) but did **not** improve, and mostly slightly
*worsened*, agreement with the vendored automatic metrics (COMET
correlation dropped for accuracy and fluency, only style improved). This is
consistent with a judge that reasons its way toward higher confidence in
already-high scores rather than toward more discriminating ones — a
genuine finding for the paper, not just an operational footnote. Style
tie-rate at 85.4% (up from 71.1%) is the most extreme shift; both regimes
still show only weak-to-moderate correlation with automatic metrics
(|ρ| < 0.35 throughout), so neither run should be over-interpreted as a
strong ground-truth proxy.
