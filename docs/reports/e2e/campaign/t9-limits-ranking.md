## Находки

1. **F1 (HIGH) — тихий обрыв прогрева: 7/12, ошибки нет.** Чекбокс обещает «Score … first 12 ¶», badge «warming k/12» исчезает, но скоры получают только §1–§7; §8–§12 остаются пустыми навсегда (стабильно ≥6 мин). Ни ошибки, ни badge «failed» — молчаливый частичный отказ (семейство известного паттерна «green ready badge over half-broken upload»). Репро: создать 40-¶ док (фикстуры T9) с включённым precompute; наблюдать `GET /api/documents/{id}` — scored замирает на 7. Вероятная причина — падения judge-вызовов (таймаут/429 под параллельной кампанией) после EVAL_RETRIES, трактуемые как «готово». Артефакты: шаги 9–10 таблицы.
2. **F2 (MEDIUM, известный, всё ещё на проде) — двойной DELETE.** Одно подтверждение confirm-диалога → два `DELETE /api/documents/18` (оба 204). Идемпотентно, но дубль-запрос жив (фиксировался 2026-07-16, не исправлен).
3. **F3 (LOW) — RU-термы в тексте не открывают попап.** Клики по `va-term-span-source` (стилизованы как интерактивные, с difficulty-цветом) не дают ничего; попап открывается только с EN-стороны (`va-term-span verdict-*`). Асимметрия сбивает с толку; grounding-инфа для RU-терма доступна только через Glossary.
4. **F4 (спека vs продукт) — «прогрев всех 40» невозможен.** Спека T9 требует «warming всех 40», продукт капит precompute первыми 12 ¶ (честная подпись «first 12 ¶, ~$0.14»). Требование спеки невыполнимо как написано — обновить спеку или дать опцию полного прогрева.
5. **N5 (note) — якорь на сверхвысоком абзаце.** Переход к §21 (4000 chars, выше вьюпорта) центрирует блок: шапка/чип скора оказываются на 240 px выше экрана. На обычных абзацах (§5/§33/§40) якорь точен.
6. **N6 (note) — сортировка Ranking сбрасывается при уходе с вкладки** (возврат — заголовок без стрелки, порядок по #). Мелкий UX.
7. **N7 (note) — unscored «—» строки при сортировке ↑ идут первыми** (трактуются как минимум). Осознанное поведение, но при триаже «худших» пользователь сперва видит 33 пустых строки.
