Ключевые решения и почему:

  • Для честного сравнения режимов взяли замороженное пересечение статей (одинаковый набор статей во всех трёх judge-прогонах) вместо сравнения на разных по размеру частично докаченных наборах.
  • --reuse-extraction добавлен специально, чтобы 3 judge-прохода по одному и тому же извлечению стоили $0 на экстракции — оплачивается только judge/label-guess вызовы.
  • 3 search-режима выбраны прямо из данных категоризации: baseline — контроль; alt-names — тест гипотезы «спасение через parenthetical-алиас в предложении» (категоризация предсказала 0/74 спасений — предсказание подтвердилось); label-guess — тест гипотезы «спасение через канонический Wikidata-лейбл» (категоризация предсказала 52/74 спасений — наибольший ожидаемый выигрыш).
  • Поле category добавлено в NER-промпт для будущей сегментации ошибок по типу сущности (см. таблицу 2c в категоризации: place/people/person доминируют среди промахов).
