## Decisions & rationale

1. **Judge provider swap, not a new client.** The repo already has a working
   CloseRouter judge pattern in `eval_grounding.py`/`wiki_eval.py`; reused it
   verbatim (model/provider/base-url env-overridable the same way) rather
   than inventing a third judge-construction path. Probed connectivity with
   a minimal call before running the real pass.

2. **Lemma fix was in-scope, not scope creep.** The literal task ("run the
   existing pipeline") technically completed on the first attempt (95 judge
   calls, 0 `judge_unavailable`) — but 29 terms flipped yellow→red, rejecting
   the demo's own headline entities (Mesopotamia, Babylon, Euphrates,
   Assyria, Sumer). Traced this to a genuine data bug, not a judge-quality
   issue: the judge's rejection reasons explicitly named the correct QID as
   "not among the provided candidates" — candidate generation was starving
   because every seed mention's `lemma` field equaled its inflected surface,
   violating the pipeline's own documented "search nominative lemma first"
   invariant (`docs/stages/terminology.md`). Verified the fix hypothesis
   empirically (`generate_candidates` with a corrected lemma vs. the raw
   inflected one) before writing the correction script. This is squarely
   "make existing things work" per the owner's working-style rule, not a new
   feature — the lemma is a documented field the pipeline already consumes.

3. **Lemma source priority: curated map first, LLM only for gaps.**
   `data/seed/lemmas.json` (327 hand-curated entries, already trusted by
   `merge_goldens.py`) covered 60/142 unique surfaces; the LLM lemmatizer
   (same CloseRouter provider) filled the remaining 82, including multi-word
   agreement a flat map can't express (`Нижней Месопотамии` →
   `Нижняя Месопотамия`). Did not write LLM output back into `lemmas.json`
   itself — kept the correction scoped to the mentions file it directly
   fixes (see NOT done).

4. **Additive-only, cannot regress a working green.** Verified from
   `candidates.py`'s own docstring/code that lemma and surface searches both
   always run and are dedup-merged (lemma first) — a corrected nominative
   lemma can only add the right entity to the candidate pool, never remove
   an existing green/exact-match path. This bounded the blast radius before
   the full re-run.

5. **SSOT for the distribution number, historical entries left alone.** Per
   doc-parity convention, moved the fact into `docs/testing/e2e-data.md` and
   made `webapp.md`/`terminology.md` link instead of duplicate. Did NOT
   rewrite the seed-refresh plan's completed C6 checklist entry with new
   numbers — that would falsify what that historical run actually produced;
   added a "Superseded" pointer instead.

6. **Makefile `pipeline`/`judge` targets removed, not redirected.** No
   `scripts/02_run_pipeline.py`/`03_run_judge.py` exist anywhere in the repo
   (grepped) — these were leftover from a different pipeline layout. No
   replacement script does the same job, so removing was the honest fix
   over guessing a redirect.
