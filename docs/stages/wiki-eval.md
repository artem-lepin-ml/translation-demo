# Stage — Wiki-eval (E1+E2 evaluation harness)

Up-link: [docs/pipeline.md](../pipeline.md). Design: [2026-07-03-wiki-eval-design.md](../superpowers/specs/2026-07-03-wiki-eval-design.md). Plan: [2026-07-03-wiki-eval-plan.md](../superpowers/plans/2026-07-03-wiki-eval-plan.md). Depends on the [terminology stage](terminology.md) (G6 `label_first` grounding, unmodified).

## Purpose

Measure the terminology extraction (E1) + Wikidata grounding (E2, G6 `label_first`) pipeline against human hyperlink annotations on 100 full Russian Wikipedia ancient-history articles (selection v2: 10 thematic sections × 10). Reports **recall** (primary metric, 3 matching modes) and 3 precision variants, sliced by thematic section (the `stratum` field carries the section slug), resolution path (`resolved_by`), and entity type (named/term), each with raw n + Wilson 95% CI. This is a standalone evaluation harness — it consumes the terminology stage's public contracts (`extract.llm_surfaces`, `grounding.LabelFirstGrounding`) but writes no code inside `grounding/`.

## Corpus (selection v2, 2026-07-05)

100 articles across **10 fixed thematic sections** of ancient history (10 per section): Sumer/Mesopotamia, Ancient Egypt, Assyria, Hittite kingdom, Phoenicia, Achaemenid Iran, Ancient India, Ancient China, Ancient Greece, Ancient Rome. Selection is deterministic and reproducible ([scripts/select_wiki_corpus.py](../../scripts/select_wiki_corpus.py), seed=42):

- **Candidate pool** — each section's Wikipedia category subtree (ns0 pages only).
- **Gate** — ≥30 unique main-namespace links in body paragraphs; earliest Wikidata date (P571/P580/P585/P569/P577) before 500 CE, undated pages kept; P31 blacklist {film, painting, museum, art museum}.
- **Binding** — an article reachable from several sections is bound to the first in fixed section order and used once.

Outputs: [data/eval/wiki/titles_v2.txt](../../data/eval/wiki/titles_v2.txt) (`title<TAB><section-slug>`; the slug becomes the GT record's `stratum` value, so metrics slice per section) and [data/eval/wiki/selection_v2.json](../../data/eval/wiki/selection_v2.json) (full audit trail: pool sizes, gate drops, per-pick links/date/QID).

**Known residue (disclosed, kept):** Wikipedia's category partition is noisy — ≈3/100 undated pages fall outside the intended period; they are retained rather than curated post hoc (owner decision 2026-07-05, avoids cherry-picking). Corpus limitations for the paper: (L1) noisy category partition; (L2) human link annotation is precise but incomplete — the basis for recall-primary reporting.

**History:** the original design (spec 2026-07-03, E-D2/E-D3) stratified 50 *hard* + 50 *typical* by an anchor-ambiguity `hardness` score. Retired 2026-07-05 together with `wiki_gt.hardness`/`select_articles`; the `stratum` field name is kept for schema compatibility, its values are now section slugs (the 20-article pilot `gt.jsonl` predates v2 and carries `stratum="typical"` throughout).

## Design decisions

- **Modules under `src/palimpsest/terminology/evaluation/`**, one responsibility each: `tokenize.py` (pinned E-D6 tokenizer, shared GT/prediction side), `wiki_gt.py` (Parsoid fetch, anchor→QID GT extraction, chronology filter; corpus selection lives in `scripts/select_wiki_corpus.py`), `predict.py` (eval-owned bridge: paragraph-chunked extractor calls with global-offset stitching → grounding pairing), `matching.py` (M1/M2/M3 tuple matching, pure), `metrics.py` (recall/precision/Wilson-CI/slice aggregation), `report.py` (this module).
- **Tuple convention**: `(token_index, surface, qid, span_len)`, global whole-article token index (no per-paragraph reset). Shared by GT and predicted tuples so `matching.py` compares them directly.
- **Real extraction entry point wired for `wiki_eval run`**: `extract.llm_surfaces(paragraph, extractor=callable) -> list[dict]` → `extract.mentions_from_surfaces(paragraph, surfaces) -> list[TermMention]`. The injected `extractor` callable is an `LLMClient`-backed closure over `extract.DEFAULT_NER_PROMPT`. `scripts/wiki_eval.py::_build_extract_fn` builds this and hands `predict.predict_tuples` an `extract_fn(paragraph) -> list[TermMention]`.
- **Provider (2026-07-05, `WIKI_EVAL_PROVIDER`)**: default `closerouter` runs the extractor **and** judge via the CloseRouter gateway (`OPENROUTER_BASE_URL`, `OPENROUTER_API_KEY`). Model and route are env-overridable: `CLOSEROUTER_MODEL` (default `google/gemini-3.1-flash-lite`) and `CLOSEROUTER_PROVIDER` (default `provider-9`), the latter pinned on a per-request `provider` field passed through `LLMConfig.extra_body`. provider-9 was verified on a 2026-07-05 probe: 10/10, ~1.4s, honest 5-token prompt, cost surfaced — the fastest/cheapest clean route. **Pin an explicit route** rather than `auto`: for some models `auto` lands on a reseller-padded provider — e.g. gpt-5.4-mini routes to provider-6, which pads ~4400 hidden prompt tokens per call (~200× input-cost trap). CloseRouter's WAF rejects the OpenAI SDK's default User-Agent — [`palimpsest.llm.client`](../../src/palimpsest/llm/client.py) sends a neutral `USER_AGENT`, mandatory or every call 403s. Set `CLOSEROUTER_MODEL=anthropic/claude-haiku-4.5` (provider-9) to measure the 2026-07-02 NER tournament winner instead. `WIKI_EVAL_PROVIDER=openrouter` (openrouter.ai) or `openai-direct` (`gpt-4o-mini` on `api.openai.com`) are gateway fallbacks; `openai-direct` measures gpt-4o-mini, not the deployed extractor.
- **Judge wiring**: same provider as the extractor (default CloseRouter `gemini-3.1-flash-lite`, pinned via `CLOSEROUTER_PROVIDER`), `max_tokens=512`, calls wrapped in [`LLMClient.complete_retrying`](../../src/palimpsest/llm/client.py) (3 attempts, 1s/3s/9s backoff, transient errors only — CloseRouter routes run ~90% success). Real per-call cost comes from `usage.cost_usd` (CloseRouter surfaces it there, not under `cost`); `BudgetGuard` keeps the identical pre-call `reserve()`/`settle()` contract plus the `MAX_JUDGE_CALLS=900` ceiling from spec Sec.11. `scripts/eval_grounding.py` shares the same provider selection. `_build_judge` returns `None` when the provider key is unset (caller falls back to `judge=None`).
- **`report.py` is pure and offline**: `render_html(metrics, meta) -> str` takes the `metrics.aggregate()` output shape directly and never calls an LLM or the network. `methodology_draft() -> str` returns spec Sec.7's EN paper paragraph verbatim (see below) — never paraphrased, copied byte-for-byte per the project's "preserve chat formulations" convention.
- **`scripts/wiki_eval.py` subcommands** (spec Sec.3 table): `build-gt` (free, deterministic from cache), `run --config <bits>` (the only paid stage: extractor + judge), `ablate` (loops `run` over the 8 `GroundingConfig` toggle combinations, sharing the Wikidata cache), `report` (pure offline recompute of `metrics.json` + `report.html` from persisted `pred.jsonl` + `gt.jsonl` — no LLM, no network).
- **Underpowered-cell flag** (n<30, `metrics.UNDERPOWERED_THRESHOLD`) renders as a greyed cell with an explicit "underpowered n<30" badge in the HTML — never silently interpreted as signal.
- **P3 (label-justified precision)** is only ever rendered inside a `resolved_by` slice, matching `metrics.precision`'s hard `ValueError` guard against an unsliced P3 aggregate (tautological on the `exact_label` path, spec Sec.4).

## Interface

```
# report.py
render_html(metrics: dict, meta: dict) -> str        # HTML fragment, project dark palette, inline CSS only
methodology_draft() -> str                            # spec Sec.7 EN paragraph, verbatim

# scripts/wiki_eval.py (argparse subcommands)
wiki_eval.py build-gt --titles <file> [--out data/eval/wiki/gt.jsonl] [--cache data/eval/wiki/pages]
wiki_eval.py run --gt <gt.jsonl> [--cache <dir>] [--config <3-bit id>] [--max-usd 40] [--dry-run]
wiki_eval.py ablate --gt <gt.jsonl> [--cache <dir>] [--max-usd 40] [--dry-run]
wiki_eval.py report --gt <gt.jsonl> --pred <run_dir> [--ablation]
```

`run`/`ablate` write `reports/terminology/wiki-eval/<config>/<run_id ISO-UTC>/pred.jsonl` (predicted tuples + full per-mention records, for `resolved_by` slicing). `report` writes `metrics.json` + `report.html` next to the `pred.jsonl` it read.

## Subtleties

- **Paragraphs are re-derived from cached HTML, not from `gt.jsonl`'s flat `tokens[]`.** `gt.jsonl` stores the whole-article token list (for GT tuple indexing), not the paragraph split `predict_tuples` needs for its chunked extractor calls. `run` re-reads the cached `<cache>/<title>.html`, re-flattens it (`tokenize.flatten`), and splits on `"\n"` — identical to what `wiki_gt.build_gt` did when it produced the tokens, so GT and prediction indices stay aligned. This means `run` requires the same HTML cache `build-gt` populated; a `pred.jsonl` re-run after clearing the cache will silently skip articles whose HTML is missing (title absent from output) rather than fail loud — a known gap, not yet a fail-loud guard (tracked below).
- **`--dry-run` forecast is a rough upper-bound, not a simulation.** It estimates escalations as `n_words / 20` mentions and 1 judge call per 3 predicted mentions — a deliberately coarse prior (spec Sec.5's cap-reconciliation note: the harness's real defense is the live `BudgetGuard` + `MAX_JUDGE_CALLS`, not forecast precision). A full 5-article cache-hit-rate pilot per spec Sec.5 is not yet implemented; the current dry-run is a floor sanity check, not the forecast described there.
- **`_canonicalize_fn`/`_p31_of_fn`** call `WikidataClient.get_entities` per QID with a local dict cache (no batching across the whole run) — fine at pilot scale, a batching pass would help before a full 100-article run if QID-lookup volume turns out to dominate wall-clock.
- **Type slice caveat inherited from spec Sec.4**: GT-side type classification (`named` vs `term`) uses anchor surface capitalization only; the extractor's own `category` field is not cross-tabbed against it yet. Per the spec, this slice should not be read as a clean named-vs-term comparison until that cross-tab is added.

## Methodology (article draft, EN)

> **Evaluation against Wikipedia link annotations.** We evaluate the terminology extraction-and-grounding component against human hyperlink annotations on 100 full Russian Wikipedia articles on ancient history, organised into ten fixed thematic sections (Sumer/Mesopotamia, Ancient Egypt, Assyria, the Hittite kingdom, Phoenicia, Achaemenid Iran, Ancient India, Ancient China, Ancient Greece, Ancient Rome), ten articles per section. Candidates from each section's category subtree pass a deterministic gate — at least 30 unique main-namespace links in body paragraphs, an earliest associated Wikidata date before 500 CE with undated pages kept, and a small instance-of blacklist for off-topic media pages — with a fixed random seed and first-section binding for pages reachable from several sections; because Wikipedia's category partition is noisy, a small off-period residue (≈3/100) survives the gate and is disclosed rather than curated post hoc. Each internal link whose target carries a Wikidata item yields a gold tuple *(token index, surface, QID)*; chronology targets (years, centuries) are excluded by target *P31*. We compare gold and predicted tuple sets under three matching modes — strict index, span overlap (primary), and document-level *(lemma, QID)* — normalizing surfaces with a shared casefold/ё-е/dash normalizer; the strict mode is a deliberate lower bound sensitive to multi-word anchor boundaries. Because human annotation is precise but incomplete, we treat **recall** as the primary metric; precision, measured against Wikipedia's non-exhaustive "don't over-link" convention, is a conservative lower bound and is reported under three complementary denominators: raw, unique-word (to offset the convention of not linking repeat mentions), and label-justified (a prediction absent from gold is credited when its surface exists as a Wikidata label — reported only per resolution path, since on the deterministic exact-label path it holds by construction). Reporting is sliced by thematic section, by the system's own resolution path (exact-label vs. LLM-disambiguated), and by entity type (named vs. lowercase term), each with per-cell Wilson 95 % confidence intervals; underpowered cells are flagged and differences within the interval are not interpreted. A full ablation over the three retrieval/matching toggles (lemma expansion, search fallbacks, alias matching) estimates each component's marginal contribution via leave-one-in / leave-one-out. This gives a transparent, reproducible measurement of a deterministic-first grounding system without recourse to a black-box entity linker as the reference.
