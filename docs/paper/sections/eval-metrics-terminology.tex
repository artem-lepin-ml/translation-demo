\paragraph{Terminology Recognition}
We evaluate terminology recognition and normalization at the document
level, the granularity the hyperlink annotation of \datasetWikipediaName{}
supports (Section~\ref{sec:wikihist-dataset}). For an article $d$, the
editor links yield the gold entity list $L_t = (e^t_1, \dots, e^t_m)$
through their deterministic mapping to Wikidata identifiers. The pipeline
under evaluation produces the predicted list $L_p = (e^p_1, \dots, e^p_n)$,
with each candidate model serving as both the extractor and the
disambiguation judge inside an otherwise fixed deterministic pipeline.
Both lists may mention the same entity repeatedly (i.e., $e_i = e_j$ for
$i \neq j$), and duplicate mentions would be counted multiple times and
bias entity-level aggregation, so we deduplicate both lists into unique
entity sets $S_p$ and $S_t$. A deterministic filter removes gold entities
from generic lexical classes that a terminology task should not reward
(languages and scripts, taxa, materials, units). Micro-averaged metrics
are calculated from True Positives ($TP$), False Positives ($FP$), and
False Negatives ($FN$) accumulated over all articles: $TP = S_p \cap S_t$,
$FP = S_p \setminus S_t$, $FN = S_t \setminus S_p$. Document-level recall
is $R_{\mathrm{doc}} = |TP| / (|TP| + |FN|)$ and document-level precision
is $P_{\mathrm{doc}} = |TP| / (|TP| + |FP|)$. Because the annotation is
sparse (Section~\ref{sec:wikihist-dataset}), a predicted entity absent
from $S_t$ is not necessarily wrong, so precision is a conservative lower
bound. We report each metric separately for named entities and for
common-noun terms, classifying every gold entity by the capitalization of
its anchor surface: a capitalized anchor marks a proper name, a lowercase
anchor marks common-noun terminology.
